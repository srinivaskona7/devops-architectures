Section 1 of 16

Environments, pip, uv and lockfiles

7 concepts · about 45 minutes

Python is the glue language of operations. Before any script is worth writing, you need a repeatable way to say which Python and which libraries it runs on. This section covers that foundation.

Goals
  • Explain why every project needs its own isolated environment
  • Create and use environments with venv, pip and uv
  • Describe a project in pyproject.toml and pin it with a lockfile
  • Install command line tools with pipx without polluting projects
1.1

Why isolated environments

In plain words

An environment is a private folder holding one Python interpreter link and the libraries for exactly one project. Two projects can then use different versions of the same library without fighting.

The problem it solves

If every script installs into the system Python, one upgrade of requests for tool A breaks tool B. Operating system tools such as dnf and apt also depend on the system Python, so a careless pip install can damage the machine.

What it does

  • Keeps each project's dependencies separate from the system and from other projects.
  • Makes a script reproducible, because the same environment can be rebuilt on a laptop, in CI and in a container.
  • Lets you delete and recreate an environment at any time, because it holds no data of its own.

See which Python you are using

pythonwhoami.py
import sys

print("interpreter:", sys.executable)
print("prefix     :", sys.prefix)
print("base prefix:", sys.base_prefix)
print("in a venv  :", sys.prefix != sys.base_prefix)
Tip

Run python -c "import sys; print(sys.prefix)" before installing anything. If it prints a system path you are about to change the global Python.

Check yourself
Why is deleting an environment safe?

It contains only installed packages, which can be recreated from pyproject.toml or a lockfile.

1.2

venv, the built in tool

In plain words

python -m venv creates an environment folder, usually .venv, using the standard library only. Activating it puts its bin directory first on your PATH.

The problem it solves

You need isolation on a server or in a container where you cannot install extra tools first.

What it does

  • Creates .venv/bin/python and a private site-packages folder.
  • source .venv/bin/activate is optional. Calling .venv/bin/python directly works the same and is clearer in scripts and cron.
  • Never commit .venv; add it to .gitignore.

Commands

bashvenv from scratch
python3 -m venv /tmp/demo-venv            # create
/tmp/demo-venv/bin/python -m pip --version   # call it without activating
/tmp/demo-venv/bin/python -m pip install --quiet rich
/tmp/demo-venv/bin/python -c "import rich; print(rich.__file__)"
rm -rf /tmp/demo-venv                     # safe to throw away
Check yourself
Why prefer .venv/bin/python over activating in cron or systemd?

There is no shell session to activate in, and the explicit path cannot pick up the wrong interpreter.

1.3

pip essentials

In plain words

pip downloads packages from an index such as PyPI and installs them into the current environment. Always run it as python -m pip so it is tied to the interpreter you mean.

The problem it solves

Running a bare pip may belong to a different Python than the python you use, and you install into the wrong place.

What it does

  • pip install name, pip install "name>=2,<3", pip install -r requirements.txt.
  • pip list, pip show name, pip freeze show what is installed.
  • pip check reports broken dependency combinations.
  • pip install -e . installs your own project in editable mode while developing.

Everyday use

bashpip commands
python3 -m venv /tmp/pipdemo
/tmp/pipdemo/bin/python -m pip install --quiet "requests>=2.31,<3"
/tmp/pipdemo/bin/python -m pip list --format=freeze | head -5
/tmp/pipdemo/bin/python -m pip show requests | head -3
/tmp/pipdemo/bin/python -m pip check
rm -rf /tmp/pipdemo
Careful

Avoid sudo pip install. If pip says the environment is externally managed, create a venv or use pipx instead of forcing it with --break-system-packages.

Check yourself
What does pip check do?

It verifies that installed packages have compatible dependencies and reports conflicts.

1.4

pyproject.toml, the project description

In plain words

pyproject.toml is one file that names your project, its Python version, its dependencies and the tools that build and check it. Every modern tool reads it.

The problem it solves

Older projects scattered this across setup.py, setup.cfg, requirements.txt and tool specific files, and executing setup.py to learn dependencies was unsafe and slow.

What it does

  • [project] holds name, version, requires-python and dependencies.
  • [project.optional-dependencies] or [dependency-groups] hold extras such as test tools.
  • [project.scripts] creates command line entry points.
  • [build-system] says which backend builds the package; [tool.*] tables configure ruff, mypy and pytest.

A realistic file

  "boto3>=1.34",
  "requests>=2.31",
  "pyyaml>=6",
]

[dependency-groups]

[build-system]

[tool.ruff]

Which table creates the opskit command?

[project.scripts], mapping a command name to module:function.

1.5

uv, a fast project manager

In plain words

uv is a single program that creates environments, installs packages, manages Python versions and writes lockfiles. It does the work of pip, venv, pip-tools and pyenv, and is much faster.

The problem it solves

Resolving and installing with pip can take minutes in CI, and juggling several tools for versions, environments and locking is easy to get wrong.

What it does

  • uv venv and uv pip install are drop in replacements for venv and pip.
  • uv init, uv add, uv remove edit pyproject.toml and the lock for you.
  • uv run cmd runs a command inside the project environment, creating it first when needed.
  • uv python install 3.12 downloads a managed interpreter.

Commands

bashuv project in five commands
uv init opskit && cd opskit
uv add boto3 requests            # runtime dependencies
uv add --dev pytest mypy ruff    # development group
uv sync                          # create .venv exactly as locked
uv run pytest -q                 # run without activating
uv python install 3.12           # fetch an interpreter if missing
uv pip install -r requirements.txt   # pip compatible mode
Picking a tool

Avoid whenthe host policy allows only the standard library

Avoid whenyou also want locking and Python version management
OptionPoetry or PDM
Choose whenthe team already uses them
Avoid whenyou are starting fresh and want fewer moving parts

Which uv command runs a program in the project environment without activating it?

uv run.

1.6

Lockfiles and reproducible installs

In plain words

pyproject.toml says what versions are acceptable. A lockfile records the exact versions, and ideally hashes, that were chosen, so every machine installs the same thing.

The problem it solves

Without a lock, "requests>=2" installs a different version next month. A tool that worked on Friday fails on Monday because a transitive dependency changed, or worse, a malicious release is pulled in silently.

What it does

  • uv lock writes uv.lock; uv sync --locked fails if the lock is out of date, which suits CI.
  • pip-compile --generate-hashes (from pip-tools) writes a requirements.txt with hashes; pip install --require-hashes -r verifies each file.
  • Commit the lock for applications and tools. Libraries usually commit only ranges.

Installing from a lock

bashStrict installs in CI
uv lock --check                      # fail if the lock does not match pyproject.toml
uv sync --locked --no-dev            # exact production set

# plain pip route
pip-compile --generate-hashes -o requirements.txt pyproject.toml
python -m pip install --require-hashes -r requirements.txt
Note

Upgrade deliberately with uv lock --upgrade-package boto3 or a scheduled Dependabot or Renovate pull request, not by accident at build time.

Check yourself
Why do hashes add security?

An installer rejects any file whose hash differs from the recorded one, so a swapped or tampered package fails.

1.7

pipx and uv tool, installing command line tools

In plain words

pipx installs a Python command line application into its own private environment and puts the command on your PATH. uv tool install does the same.

The problem it solves

Tools such as ruff, awscli, pre-commit or httpie are not libraries of your project. Installing them into a project pollutes its dependencies; installing globally risks conflicts.

What it does

  • pipx install name makes one isolated venv per tool.
  • pipx run name runs a tool once without keeping it.
  • pipx inject tool extra adds a plugin library into that tool's environment.
  • pipx upgrade-all refreshes everything; pipx ensurepath fixes PATH.

Commands

bashInstalling tools
python3 -m pip install --user pipx
pipx ensurepath
pipx install ruff
pipx install "git+https://github.com/example/opskit.git"   # your own tool from git
pipx run cowsay hello                                      # one-off, nothing kept
uv tool install ruff                                       # the uv equivalent
pipx list
Check yourself
When would you choose pipx run?

To try a tool once or run it in a script without leaving it installed.

Packaging, project layout and typing

8 concepts · about 45 minutes

A script that grows beyond one file needs a shape. This section turns loose scripts into a small package and adds types so mistakes are found before they reach production.

Goals
  • Lay out an operations project so it is importable, testable and installable
  • Build a wheel and expose commands through entry points
  • Add type hints and check them with mypy
  • Model structured data with dataclasses, TypedDict and Protocol
2.1

Modules and the src layout

In plain words

A module is one .py file; a package is a folder of modules with an __init__.py. The src layout puts the package under src/ so tests import the installed code, not whatever sits in the current folder.

The problem it solves

Scripts that import each other by relative file position work on your laptop and break in cron, in CI or in a container, because the working directory differs.

What it does

  • Keeps code in src/opskit/, tests in tests/, and configuration in pyproject.toml.
  • pip install -e . makes import opskit work anywhere in that environment.
  • if __name__ == "__main__": lets a file act as both a library and a script.

A minimal module

pythonsrc/opskit/report.py
"""Format simple tables for terminals."""
from __future__ import annotations


def render_table(rows: list[dict[str, object]], columns: list[str]) -> str:
    widths = {c: max(len(c), *(len(str(r.get(c, ""))) for r in rows)) for c in columns} if rows else {c: len(c) for c in columns}
    head = "  ".join(c.ljust(widths[c]) for c in columns)
    lines = [head, "  ".join("-" * widths[c] for c in columns)]
    for r in rows:
        lines.append("  ".join(str(r.get(c, "")).ljust(widths[c]) for c in columns))
    return "\n".join(lines)


if __name__ == "__main__":
    print(render_table([{"name": "web-1", "state": "running"}], ["name", "state"]))
Check yourself
Why use a src layout?

It forces tests and tools to import the installed package, which catches missing files and wrong imports early.

2.2

Building a wheel

In plain words

A wheel is a ready to install archive of your package. Building one turns your code into something pip or uv can install anywhere without running your build scripts.

The problem it solves

Copying a folder to a server leaves out dependency declarations and entry points, and gives no version you can roll back to.

What it does

  • python -m build (or uv build) produces dist/opskit-0.1.0-py3-none-any.whl and a source archive.
  • The wheel carries metadata, so pip install dist/*.whl also installs the declared dependencies.
  • Upload to a private index (Artifactory, CodeArtifact, devpi) so teammates and servers can install by version.

Commands

bashBuild and test the wheel locally
python -m pip install build
python -m build                          # creates dist/
python -m venv /tmp/wheel-test
/tmp/wheel-test/bin/python -m pip install dist/*.whl
/tmp/wheel-test/bin/opskit --help        # the entry point exists
python -m twine upload --repository-url "$INDEX_URL" dist/*   # publish to your index
Tip

Always install the built wheel into a clean environment and run it once. That test catches files missing from the package.

Check yourself
What does the wheel give you that a copied folder does not?

A version number, declared dependencies and entry points, installable with one command.

2.3

Entry points and console scripts

In plain words

An entry point maps a command name to a Python function. After installation, typing opskit runs that function, with no python path/to/file.py needed.

The problem it solves

Operators should not need to know where a script lives or which interpreter it needs. A shebang pointing at a laptop path fails on every other machine.

What it does

  • [project.scripts] opskit = "opskit.cli:main" creates an executable in the environment's bin directory.
  • The function should return an integer exit code; the generated wrapper passes it to sys.exit.
  • python -m opskit works too if you add a __main__.py.

Wiring it

pythonsrc/opskit/cli.py
from __future__ import annotations

import sys
from collections.abc import Sequence


def main(argv: Sequence[str] | None = None) -> int:
    args = list(sys.argv[1:] if argv is None else argv)
    if not args or args[0] in {"-h", "--help"}:
        print("usage: opskit <command>")
        return 0
    print(f"unknown command: {args[0]}", file=sys.stderr)
    return 2


if __name__ == "__main__":
    raise SystemExit(main())
pythonsrc/opskit/__main__.py
from opskit.cli import main

raise SystemExit(main())
Check yourself
What should main return?

An integer exit code, 0 for success, so shells and CI can detect failure.

2.4

Installing as a command

In plain words

Publish the package to a private index, or install straight from Git, and users get a real command on their PATH through the entry point you declared.

The problem it solves

"Clone the repo, make a venv, run python scripts/x.py" is a barrier, and every copy drifts from the others.

What it does

  • pipx install opskit (or uv tool install opskit) gives one isolated environment per tool and the opskit command.
  • pipx install git+https://git.example.com/ops/opskit@v1.2.0 pins a Git tag.
  • opskit --version should print the installed version from package metadata (importlib.metadata.version).
  • Tag releases; upgrade deliberately with pipx upgrade opskit.

Version from metadata

pythonversion.py
from importlib.metadata import PackageNotFoundError, version


def tool_version(name: str = "opskit") -> str:
    try:
        return version(name)
    except PackageNotFoundError:
        return "0+unknown"      # running from a source checkout


print(tool_version("pip"), tool_version("not-installed-xyz"))
Check yourself
Where should --version read the number from?

Package metadata, so it always matches the installed release.

2.5

Type hints, the basics

In plain words

A type hint states what kind of value a variable, argument or return is, for example str, int or list[str]. Python ignores hints at run time; tools read them.

The problem it solves

In a long ops script a function that sometimes returns None and sometimes a string causes a crash at 3 a.m. when the rare path is hit. Hints make that visible when you edit.

What it does

  • def f(x: int, name: str | None = None) -> list[str]: documents inputs and outputs.
  • Builtin generics (list[str], dict[str, int]) work from Python 3.9, and X | None from 3.10.
  • Editors use hints for completion and warnings; mypy checks them across the project.

Example

pythonHints in a real helper
from __future__ import annotations


def parse_size(text: str) -> int:
    """Turn '10G', '512M' or '100' into bytes."""
    units = {"K": 1024, "M": 1024**2, "G": 1024**3, "T": 1024**4}
    text = text.strip().upper()
    if text and text[-1] in units:
        return int(float(text[:-1]) * units[text[-1]])
    return int(text)


def first_match(names: list[str], prefix: str) -> str | None:
    for n in names:
        if n.startswith(prefix):
            return n
    return None


print(parse_size("10G"), parse_size("512M"), first_match(["db-1", "web-1"], "web"))
Check yourself
Does Python enforce hints at run time?

No; they are checked by tools such as mypy and used by editors.

2.6

Checking with mypy

In plain words

mypy reads your hints and reports places where the code contradicts them, without running the code.

The problem it solves

Tests only cover paths you thought of. Types catch whole classes of bugs, such as passing None into a function that needs a string, for every path.

What it does

  • mypy src reports errors with file and line.
  • strict = true in [tool.mypy] turns on the stricter checks; start with it on new code.
  • Libraries without hints need stubs such as types-requests and types-PyYAML, or an ignore for that module only.
  • Run it in CI beside tests and ruff so regressions fail the build.

Configuration and a caught bug

tomlpyproject.toml tool settings
[tool.mypy]
python_version = "3.11"
strict = true
files = ["src"]

[[tool.mypy.overrides]]
module = ["boto3.*", "botocore.*"]
ignore_missing_imports = true
pythonmypy would reject this
def find_owner(tags: dict[str, str]) -> str:
    return tags.get("owner")   # error: returns "str | None", declared "str"


def find_owner_fixed(tags: dict[str, str]) -> str:
    return tags.get("owner", "unknown")
Check yourself
What is the bug in find_owner?

dict.get can return None, but the declared return type is str.

2.7

Dataclasses and TypedDict for structured data

In plain words

A dataclass is a small class that just holds named fields. A TypedDict describes the shape of a plain dictionary, such as a JSON object from an API.

The problem it solves

Passing raw dictionaries around means typos in keys ("intance_id") only fail when that line runs, and nobody knows what keys exist.

What it does

  • @dataclass(frozen=True) gives an immutable record with __init__, __repr__ and equality for free.
  • asdict() converts it back to a dictionary for JSON output.
  • TypedDict documents API payloads without changing them; mypy checks the keys.

Example

pythonA volume record
from __future__ import annotations

import json
from dataclasses import asdict, dataclass, field
from typing import TypedDict


class ApiVolume(TypedDict):
    VolumeId: str
    Size: int
    State: str

3.3

Atomic writes and temporary files

In plain words

An atomic write writes the new content to a temporary file in the same folder and then renames it over the target. A rename is a single step, so readers see either the old file or the new one, never half of it.

The problem it solves

If a script crashes or the disk fills while writing a config or state file directly, the file is left truncated, and the next run or another program reads garbage.

What it does

  • tempfile.NamedTemporaryFile(dir=target.parent, delete=False) makes a temp file on the same filesystem.
  • os.fsync asks the OS to flush data to disk before the rename.
  • os.replace(tmp, target) swaps atomically on the same filesystem, on Linux and Windows.

Helper

pythonatomic_write.py
from __future__ import annotations

import os
import tempfile
from pathlib import Path


def atomic_write_text(target: Path, text: str) -> None:
    target.parent.mkdir(parents=True, exist_ok=True)
    fd, tmp_name = tempfile.mkstemp(dir=target.parent, prefix=target.name + ".")
    try:
        with os.fdopen(fd, "w", encoding="utf-8") as f:
            f.write(text)
            f.flush()
            os.fsync(f.fileno())
        os.replace(tmp_name, target)
    except BaseException:
        Path(tmp_name).unlink(missing_ok=True)
        raise


with tempfile.TemporaryDirectory() as d:
    p = Path(d) / "state.json"
    atomic_write_text(p, '{"version": 1}')
    atomic_write_text(p, '{"version": 2}')
    print(p.read_text())
Check yourself
Why must the temp file be in the same folder?

4.2

Avoiding shell injection

In plain words

A shell interprets characters such as ;, |, $() and backticks. If untrusted text reaches a shell command line, it can run extra commands. Passing a list of arguments with no shell avoids the whole problem.

The problem it solves

subprocess.run(f"ping {host}", shell=True) with host = "x; rm -rf /" runs two commands. Hostnames, branch names, and ticket titles all come from outside your control.

What it does

  • Default to shell=False with a list of arguments, so each item reaches the program as is.
  • When you must build a shell string, quote parts with shlex.quote.
  • Use -- before user supplied values so they are not read as options.
  • Validate input against an allow list or pattern first.

Safe pattern

import re

HOST_RE = re.compile(r"^[A-Za-z0-9.-]{1,253}$")

        raise ValueError(f"invalid host: {host!r}")
    # list form: the value is one argument, never shell syntax
    return [sys.executable, "-c", "import sys; print('would ping', sys.argv[1])", host]

In plain words

What it does

4.4

Exit codes and standard streams

In plain words

Every program ends with an exit code: 0 means success, anything else means failure. It prints results to stdout and diagnostics to stderr, so pipelines can separate them.

The problem it solves

A script that prints "error" but exits 0 makes CI green on a failure. A script that mixes logs into stdout breaks | jq and other consumers.

What it does

  • Exit 0 on success; use 1 for a generic failure and 2 for bad usage (argparse does this).
  • Use distinct codes for distinct outcomes when callers act on them, for example 3 for "findings present".
  • Write data to stdout, messages to stderr (print(..., file=sys.stderr) or logging).
  • Raise SystemExit(code) from main, not scattered sys.exit deep in helpers.

6.1

The request and response cycle

In plain words

An HTTP call sends a method (GET, POST, PUT, PATCH, DELETE), a URL, headers and an optional body, and receives a status code, headers and a body.

The problem it solves

Treating an API call as "it either works or throws" hides the real outcomes: 4xx means you made a mistake, 5xx means the server failed, and a network error means you do not know what happened.

What it does

  • 2xx success, 3xx redirect, 4xx client error (401 unauthenticated, 403 forbidden, 404 missing, 429 rate limited), 5xx server error.
  • GET, PUT and DELETE are meant to be idempotent; POST usually is not.
  • Always parse the body according to Content-Type, and read error bodies; they usually explain the failure.

6.2

6.3

In plain words

A requests.Session keeps connections open between calls and shares headers, authentication and cookies. It is faster and shorter to write than separate calls.

The problem it solves

Each bare requests.get opens a new TCP and TLS connection. Calling an API a thousand times that way is slow and strains the server.

What it does

  • Use with requests.Session() as s: so connections close.
  • A session has no global timeout; wrap calls or subclass to inject one.

6.4

Retries with backoff in requests

In plain words

A retry tries a failed call again. Backoff waits longer between tries, with a little random jitter, so many clients do not hammer a recovering server at the same moment.

The problem it solves

Networks drop packets and services return 502 or 429 for a few seconds. A script without retries fails on a blip; a script with instant retries makes outages worse.

What it does

  • Mount HTTPAdapter(max_retries=Retry(...)) on a session; Retry comes from urllib3.util.retry.
  • status_forcelist=[429, 500, 502, 503, 504] chooses what to retry.
  • backoff_factor=0.5 waits roughly 0.5, 1, 2, 4 seconds and respect_retry_after_header honours the server's hint.
  • Only retry methods that are safe to repeat, set with allowed_methods.

Configuring Retry

pythonretry_session.py
import requests
from requests.adapters import HTTPAdapter
from urllib3.util.retry import Retry


def make_session() -> requests.Session:
    retry = Retry(
        total=5,
        connect=3,
        backoff_factor=0.5,
        status_forcelist=[429, 500, 502, 503, 504],
        allowed_methods=frozenset({"GET", "HEAD", "PUT", "DELETE", "OPTIONS"}),
        respect_retry_after_header=True,
    )
    s = requests.Session()
    adapter = HTTPAdapter(max_retries=retry)
    s.mount("https://", adapter)
    s.mount("http://", adapter)
    return s


resp = make_session().get("https://api.example.com/v1/items", timeout=10)

In plain words

Large lists are returned in pages. The API tells you how to get the next page: a page number, an offset, a cursor token, or a Link header.

The problem it solves

In plain words

Clients versus resources

In plain words

A client maps one to one to the AWS API: methods like describe_instances return dictionaries. A resource is an object oriented wrapper (s3.Bucket("x").objects.all()).

The problem it solves

Mixing styles randomly makes code hard to follow, and resources hide the API calls that cost money or hit limits.

What it does

  • Clients cover every service, are always current, and give full control. Prefer them for new code.
  • Resources exist only for some services (S3, EC2, DynamoDB, IAM, SQS and a few more) and are in maintenance mode: no new features.
  • Client responses include ResponseMetadata; errors arrive as botocore.exceptions.ClientError.

Waiters

In plain words

A waiter polls AWS until a resource reaches a state, such as an instance running or a snapshot completed, and raises an error if it does not within a limit.

The problem it solves

Hand written while True: sleep() loops forget timeouts and check the wrong field, leaving scripts that hang or continue too early.

What it does

  • Failure raises botocore.exceptions.WaiterError.
  • client.waiter_names lists what exists for that service.

Example

  • Client objects also expose modelled exceptions as client.exceptions.NoSuchBucket.
  • botocore.exceptions.NoCredentialsError, EndpointConnectionError are separate, non-ClientError cases.

  • Amounts are strings; convert with Decimal, not float.
  • Each API request is billed (about one cent), so cache and do not poll in loops. The service endpoint is in us-east-1.

Example

pythoncost_by_service.py
from decimal import Decimal

import boto3

ce = boto3.client("ce", region_name="us-east-1")


def cost_by_service(start: str, end: str) -> list[tuple[str, Decimal]]:
    totals: dict[str, Decimal] = {}
    token = None
    while True:
        kwargs = dict(
            TimePeriod={"Start": start, "End": end},
            Granularity="MONTHLY",
            Metrics=["UnblendedCost"],
            GroupBy=[{"Type": "DIMENSION", "Key": "SERVICE"}],
        )
        if token:
            kwargs["NextPageToken"] = token
        resp = ce.get_cost_and_usage(**kwargs)
        for period in resp["ResultsByTime"]:
            for g in period["Groups"]:
                amount = Decimal(g["Metrics"]["UnblendedCost"]["Amount"])
                totals[g["Keys"][0]] = totals.get(g["Keys"][0], Decimal(0)) + amount
        token = resp.get("NextPageToken")
        if not token:
            break
    return sorted(totals.items(), key=lambda kv: kv[1], reverse=True)


for name, amount in cost_by_service("2026-01-01", "2026-02-01")[:10]:
    print(f"{name:45} {amount:>10.2f}")

Watching for changes

In plain words

A watch keeps a connection open and streams events (ADDED, MODIFIED, DELETED) as objects change. Controllers and notifiers use it instead of polling.

The problem it solves

Polling every few seconds wastes API calls and still misses short lived changes between polls.

  • watch.Watch().stream(v1.list_namespaced_pod, "default", timeout_seconds=60) yields dicts with type and object.

  • Track resource_version to resume without missing events; on 410 Gone, list again and restart.
  • For serious controllers prefer a framework (kopf) that handles this.

Example

    try:
        w = watch.Watch()

            rv = pod.metadata.resource_version

        if exc.status == 410:           # resource version too old

            continue

pythonk8s_report.py
from __future__ import annotations

from collections import defaultdict

CPU_SUFFIX = {"m": 0.001}
MEM_SUFFIX = {"Ki": 1024, "Mi": 1024**2, "Gi": 1024**3, "K": 1000, "M": 1000**2, "G": 1000**3}


def cpu_cores(q: str | None) -> float:
    if not q:
        return 0.0
    return float(q[:-1]) * CPU_SUFFIX["m"] if q.endswith("m") else float(q)


def mem_bytes(q: str | None) -> int:
    if not q:
        return 0
    for suf in sorted(MEM_SUFFIX, key=len, reverse=True):
        if q.endswith(suf):
            return int(float(q[: -len(suf)]) * MEM_SUFFIX[suf])
    return int(q)


def summarise(pods: list[dict]) -> tuple[dict[str, dict[str, float]], list[str]]:
    totals: dict[str, dict[str, float]] = defaultdict(lambda: {"cpu": 0.0, "mem": 0.0, "pods": 0})
    missing: list[str] = []
    for p in pods:
        ns = p["namespace"]
        totals[ns]["pods"] += 1
        for c in p["containers"]:
            req = c.get("requests", {})
            totals[ns]["cpu"] += cpu_cores(req.get("cpu"))
            totals[ns]["mem"] += mem_bytes(req.get("memory"))
            if not req or not c.get("limits"):
                missing.append(f"{ns}/{p['name']}/{c['name']}")
    return dict(totals), missing


sample = [
    {"namespace": "shop", "name": "web-1", "containers": [
        {"name": "app", "requests": {"cpu": "250m", "memory": "128Mi"}, "limits": {"memory": "256Mi"}}]},
    {"namespace": "shop", "name": "job-1", "containers": [{"name": "run"}]},
]
totals, missing = summarise(sample)
for ns, t in totals.items():
    print(f"{ns:10} pods={int(t['pods'])} cpu={t['cpu']:.2f} mem={t['mem'] / 1024**2:.0f}Mi")
print("missing:", missing)

12.1

The operator pattern

In plain words

You describe what you want in a custom resource (for example kind: Database). A controller watches those objects and keeps reality equal to the description. This comparison and correction is called reconciliation.

The problem it solves

Running a stateful application by hand needs runbooks: create the volume, the secret, the service, then do it again after failure. Humans forget steps and cannot react at 3 a.m.

What it does

  • Declarative: you state the desired state; the controller makes it so, repeatedly.
  • Level triggered: it should work out what to do from the current state, not from the event alone.
  • Reconciliation must be idempotent because it may run many times.

Use operators sparingly

Tip

Write an operator only when you have domain logic that must run continuously. For a one off job a CronJob or script is simpler and safer.

Check yourself
Why must reconciliation be idempotent?

It runs repeatedly for the same object, and running it twice must give the same result as once.

In plain words

The operator creates a StatefulSet, Service or Secret for each custom object. Children carry an owner reference, so deleting the parent deletes them, and creation must tolerate "already exists".

The problem it solves

If a handler creates a Service and then crashes, the retry creates it again and fails with 409, or leaves duplicates after a restart.

What it does

  • kopf.adopt(obj) adds ownerReferences and labels to a child dictionary.
  • Create with the Kubernetes client and treat 409 AlreadyExists as success, or patch instead.
  • Name children deterministically from the parent (f"{name}-svc"), never randomly.
  • Garbage collection removes children when the owner is deleted, so a delete handler is often unnecessary.

Idempotency, retries and concurrency

8 concepts · about 55 minutes

Automation runs unattended, fails halfway and gets restarted. Three habits make that survivable: operations that can safely repeat, retries that are polite, and concurrency that is bounded.

Goals
  • Design automation so that running it twice is safe
  • Retry transient failures with exponential backoff and jitter using tenacity
  • Choose between threads, asyncio and processes for a job
  • Bound parallelism and collect errors from concurrent work
13.1

Idempotency

In plain words

An operation is idempotent if doing it twice leaves the same result as doing it once. "Ensure the bucket exists" is idempotent; "create a bucket" is not, because the second call fails.

The problem it solves

Jobs are interrupted, retried by schedulers and re-run by humans. Non idempotent scripts create duplicates, send double notifications or crash on the second run.

What it does

  • Describe the desired state ("tag X must be Y") and make changes only if the current state differs.
  • Check first, then act; treat "already exists" or "already gone" as success.
  • Use deterministic names and keys instead of random ones.
  • Record progress in the system itself (a tag, a marker object) rather than in memory.

Ensure helpers

from __future__ import annotations


def ensure_tags(current: dict[str, str], desired: dict[str, str]) -> dict[str, str]:
    """Return only the tags that must be written."""
    return {k: v for k, v in desired.items() if current.get(k) != v}


current = {"Owner": "platform"}
desired = {"Owner": "platform", "Env": "prod", "CostCenter": "1234"}
todo = ensure_tags(current, desired)

print("second run writes:", ensure_tags(current, desired))

13.2

Retry design rules

In plain words

Retry only failures that may go away: timeouts, throttling, 5xx. Never retry failures that will repeat: bad credentials, validation errors, not found. Limit attempts and total time.

The problem it solves

Blind retries hide bugs, multiply load on a struggling service, and make a failing job run for hours.

What it does

  • Exponential backoff doubles the wait each time (1, 2, 4, 8 seconds up to a cap).
  • Jitter adds randomness so many clients spread out.
  • A deadline or attempt limit bounds total time; after it, fail clearly.
  • Only retry idempotent operations, or use idempotency keys.

Hand written backoff

pythonbackoff.py
import random
import time


def retry(fn, attempts=5, base=0.1, cap=2.0, retry_on=(ConnectionError, TimeoutError)):
    for i in range(1, attempts + 1):
        try:
            return fn()
        except retry_on as exc:
            if i == attempts:
                raise
            delay = min(cap, base * 2 ** (i - 1)) * random.uniform(0.5, 1.0)
            print(f"attempt {i} failed ({exc}); sleeping {delay:.2f}s")
            time.sleep(delay)


calls = {"n": 0}


def flaky():
    calls["n"] += 1
    if calls["n"] < 3:
        raise ConnectionError("blip")
    return "ok"


print(retry(flaky))

Why add jitter?

It spreads out retries from many clients so they do not all hit the service together.

13.3

tenacity decorators

In plain words

tenacity is a library that wraps a function with retry rules written declaratively: when to stop, how long to wait, which exceptions to retry, and what to log.

The problem it solves

Hand written loops get edge cases wrong: no cap, no jitter, retrying the wrong exception, losing the original error.

What it does

  • @retry(stop=stop_after_attempt(5) | stop_after_delay(60), wait=wait_exponential_jitter(initial=1, max=30), retry=retry_if_exception_type(...), reraise=True).
  • before_sleep_log(logger, logging.WARNING) records each retry.
  • Retrying(...) as an iterator retries a block of code instead of a function.
  • Works with async def functions as well.

13.4

Timeouts, deadlines and circuit breakers

In plain words

A timeout bounds one call. A deadline bounds a whole operation including retries. A circuit breaker stops calling a dependency that keeps failing, giving it time to recover.

The problem it solves

Retries multiplied by timeouts can make a job last far longer than anyone expects. Hammering a dead service keeps it dead.

What it does

  • Set connect and read timeouts on every network call.
  • Compute deadline = time.monotonic() + budget and pass the remaining time to each attempt.
  • A breaker has three states: closed (normal), open (fail fast), half open (try one request).
  • Fail fast and report which dependency is unhealthy.

A tiny breaker

pythonbreaker.py
import time


class Breaker:
    def __init__(self, limit=3, reset_after=0.2):
        self.limit, self.reset_after = limit, reset_after
        self.failures, self.opened_at = 0, None

    def call(self, fn):
        if self.opened_at and time.monotonic() - self.opened_at < self.reset_after:
            raise RuntimeError("circuit open")
        try:
            result = fn()
        except Exception:
            self.failures += 1
            if self.failures >= self.limit:
                self.opened_at = time.monotonic()
            raise
        self.failures, self.opened_at = 0, None
        return result


def bad():
    raise OSError("down")


b = Breaker()
for _ in range(4):
    try:
        b.call(bad)
    except Exception as e:
        print(type(e).__name__, e)
time.sleep(0.25)
print(b.call(lambda: "recovered"))

13.5

Threads for I/O bound work

In plain words

A thread runs code at the same time as other threads inside one process. Python threads cannot run Python code truly in parallel (the GIL), but they overlap well while waiting on network or disk.

The problem it solves

Calling an API for 500 resources one by one wastes minutes waiting for replies.

What it does

  • Good for boto3, HTTP and file I/O; not for pure computation.
  • ThreadPoolExecutor(max_workers=10) provides a pool with a bound.
  • boto3 clients are thread safe; sessions are not shared across threads (create one per thread).
  • Limit workers to what the remote service tolerates.

import time
from concurrent.futures import ThreadPoolExecutor, as_completed


def probe(name: str) -> tuple[str, float]:
    start = time.perf_counter()
    time.sleep(0.2)                       # stands for a network call
    return name, time.perf_counter() - start


names = [f"host-{i}" for i in range(20)]
start = time.perf_counter()
results, errors = [], []
with ThreadPoolExecutor(max_workers=10) as pool:
    futures = {pool.submit(probe, n): n for n in names}
    for fut in as_completed(futures):
        try:
            results.append(fut.result())
        except Exception as exc:          # one failure must not hide the others

13.6

asyncio

In plain words

asyncio runs many tasks on one thread. A task gives up control at each await, so while one waits for a reply others progress. It scales to thousands of concurrent waits.

The problem it solves

Threads cost memory and need locks; thousands of them are impractical. Some libraries (httpx, aiobotocore, asyncpg) are written for async.

What it does

  • async def defines a coroutine; await pauses it; asyncio.run(main()) starts the loop.
  • asyncio.gather runs many together; asyncio.TaskGroup (Python 3.11) cancels siblings on failure.
  • asyncio.timeout(5) bounds a block; Semaphore bounds parallelism.
  • Never call blocking functions such as time.sleep or requests.get inside a coroutine; use asyncio.to_thread for those.

Example

pythonasync_tasks.py
import asyncio


async def probe(name: str, delay: float, sem: asyncio.Semaphore) -> str:
    async with sem:
        await asyncio.sleep(delay)
        if name == "bad":
            raise RuntimeError("boom")
        return name


async def main() -> None:
    sem = asyncio.Semaphore(3)
    names = ["a", "b", "bad", "c"]
    results = await asyncio.gather(*(probe(n, 0.1, sem) for n in names), return_exceptions=True)
    for n, r in zip(names, results):
        print(n, "->", repr(r))
    async with asyncio.timeout(1):
        print(await asyncio.to_thread(sum, range(1000)))


asyncio.run(main())

In plain words

13.8

Rate limiting and shared state safely

In plain words

When many workers call one service, you need a shared limit. When they update shared data, you need a lock or, better, no shared mutable data at all.

The problem it solves

Ten threads each retrying aggressively exceed an API limit together. Two threads appending to one list or counter can lose updates.

What it does

  • A Semaphore caps simultaneous calls; a token bucket caps calls per second.
  • queue.Queue passes work between threads safely; threading.Lock guards counters.
  • Prefer returning results from workers and combining them in the main thread.
  • Log with thread names or task ids to follow events.

Token bucket

pythonrate_limit.py
import threading
import time


class RateLimiter:
    def __init__(self, per_second: float) -> None:
        self.interval = 1.0 / per_second
        self.lock = threading.Lock()
        self.next_time = time.monotonic()

    def wait(self) -> None:
        with self.lock:
            now = time.monotonic()
            delay = max(0.0, self.next_time - now)
            self.next_time = max(now, self.next_time) + self.interval
        if delay:
            time.sleep(delay)


rl = RateLimiter(per_second=50)
start = time.monotonic()
for _ in range(10):
    rl.wait()
print(f"10 calls took {time.monotonic() - start:.2f}s")

It avoids locks and lost updates; the main thread merges the results.

  • Failing cases are saved so the next run replays them.
  • Keep properties fast and pure.

15.1

Prometheus metric types

In plain words

Prometheus scrapes numbers over HTTP. Each number is a metric of one of four types: counter, gauge, histogram or summary, and may have labels such as region="eu-west-1".

The problem it solves

Choosing the wrong type gives graphs and alerts that mislead. A counter used for "current queue size" cannot go down; a gauge used for "requests served" loses events between scrapes.

What it does

  • Counter: only goes up (requests, errors). Query it with rate().
  • Gauge: goes up and down (queue length, temperature, idle volumes).
  • Histogram: counts observations in buckets (request duration) so you can compute percentiles with histogram_quantile().
  • Keep label values to a small, known set; one label per user id would create millions of series.

Parsing logs with regular expressions

In plain words

A log line is text with a pattern. A regular expression with named groups turns each line into fields you can count and group.

The problem it solves

grep | awk | sort | uniq pipelines are hard to maintain and cannot compute percentiles or join with other data.

What it does

  • re.compile(r"...(?P<status>\d{3})...") once, then .match(line) per line.
  • Named groups give a dictionary with m.groupdict().
  • Skip non matching lines but count them, so format changes are noticed.
  • Parse timestamps with datetime.strptime; keep them timezone aware.

import re
from datetime import datetime

LINE = re.compile(
    r'(?P<ip>\S+) \S+ \S+ \[(?P<ts>[^\]]+)\] "(?P<method>[A-Z]+) (?P<path>\S+) [^"]*" '
    r'(?P<status>\d{3}) (?P<size>\d+|-) "[^"]*" "(?P<agent>[^"]*)" (?P<ms>\d+)'
)


def parse(line: str) -> dict | None:
    m = LINE.match(line)
    if not m:
        return None
    d = m.groupdict()
    d["status"] = int(d["status"])
    d["size"] = 0 if d["size"] == "-" else int(d["size"])
    d["ms"] = int(d["ms"])
    d["ts"] = datetime.strptime(d["ts"], "%d/%b/%Y:%H:%M:%S %z")
    return d

  • Prints a short text report, or JSON for other tools.
  • Handles gzip files by opening with gzip.open when the name ends with .gz.

from __future__ import annotations

import gzip
import io
import re
import statistics
from collections import Counter, defaultdict
from pathlib import Path

LINE = re.compile(r'"(?P<method>[A-Z]+) (?P<path>[^ ?]+)[^"]*" (?P<status>\d{3}) \S+ (?P<ms>\d+)$')


def open_text(path: Path):
    if path.suffix == ".gz":
        return io.TextIOWrapper(gzip.open(path, "rb"), encoding="utf-8", errors="replace")
    return path.open(encoding="utf-8", errors="replace")


def summarise(lines) -> dict:
    status = Counter()
    by_path: dict[str, list[int]] = defaultdict(list)
    bad = 0
    for line in lines:
        m = LINE.search(line.rstrip())
        if not m:
            bad += 1
            continue
        status[m["status"]] += 1
        by_path[m["path"]].append(int(m["ms"]))
    all_ms = [ms for v in by_path.values() for ms in v]
    p95 = statistics.quantiles(all_ms, n=20)[18] if len(all_ms) >= 2 else (all_ms[0] if all_ms else 0)
    slowest = sorted(((statistics.mean(v), p, len(v)) for p, v in by_path.items()), reverse=True)[:3]
    return {"status": dict(status), "p95_ms": p95, "unparsed": bad,
            "slowest": [{"path": p, "avg_ms": round(a), "hits": n} for a, p, n in slowest]}

import ssl
import time

WARN_DAYS = 21


def days_left(not_after: str, now: float | None = None) -> float:
    expires = ssl.cert_time_to_seconds(not_after)
    return (expires - (now if now is not None else time.time())) / 86400


def classify(days: float) -> str:
    if days < 0:
        return "EXPIRED"
    return "WARN" if days < WARN_DAYS else "OK"


now = ssl.cert_time_to_seconds("Jan  1 00:00:00 2026 GMT")
for text in ("Jan 10 00:00:00 2026 GMT", "Feb  1 00:00:00 2026 GMT", "Dec 25 00:00:00 2025 GMT"):

import socket
import ssl
import sys
from concurrent.futures import ThreadPoolExecutor

from certcheck_core import classify, days_left


def check(host: str, port: int = 443) -> tuple[str, float | None, str]:
    ctx = ssl.create_default_context()
    try:
        with socket.create_connection((host, port), timeout=5) as sock:
            with ctx.wrap_socket(sock, server_hostname=host) as tls:
                days = days_left(tls.getpeercert()["notAfter"])
        return host, days, classify(days)
    except (OSError, ssl.SSLError) as exc:
        return host, None, f"ERROR {type(exc).__name__}"


if __name__ == "__main__":
    hosts = sys.argv[1:] or ["example.com"]
    with ThreadPoolExecutor(max_workers=10) as pool:
        results = list(pool.map(check, hosts))
    for host, days, state in results:
        print(f"{host:35} {'-' if days is None else f'{days:6.1f}'} {state}")
    sys.exit(3 if any(s != "OK" for _, _, s in results) else 0)

pythonalert_state.py
import json
import tempfile
import time
from pathlib import Path

REMIND_AFTER = 24 * 3600


def should_notify(state_path: Path, key: str, status: str, now: float) -> bool:
    state = json.loads(state_path.read_text()) if state_path.exists() else {}
    last = state.get(key, {"status": "OK", "at": 0})
    changed = last["status"] != status
    reminder = status != "OK" and now - last["at"] > REMIND_AFTER
    if changed or reminder:
        state[key] = {"status": status, "at": now}
        state_path.write_text(json.dumps(state))
        return True
    return False


p = Path(tempfile.mkdtemp()) / "state.json"
t = time.time()
print(should_notify(p, "cert:example.com", "WARN", t))        # first warning
print(should_notify(p, "cert:example.com", "WARN", t + 60))   # same state, quiet
print(should_notify(p, "cert:example.com", "OK", t + 120))    # recovered

    size_gb: int
    vol_type: str
    age_days: int
    monthly_cost: float


def find_idle(volumes: list[dict], now: datetime, min_age_days: int = 14) -> list[IdleVolume]:
    out = []
    for v in volumes:
        if v["State"] != "available":
            continue
        tags = {t["Key"]: t["Value"] for t in v.get("Tags", [])}
        if tags.get("keep", "").lower() == "true":
            continue
        age = (now - v["CreateTime"]).days
        if age < min_age_days:
            continue
        price = PRICE_GB_MONTH.get(v["VolumeType"], 0.10)
        out.append(IdleVolume(v["VolumeId"], v["Size"], v["VolumeType"], age, round(v["Size"] * price, 2)))
    return sorted(out, key=lambda x: x.monthly_cost, reverse=True)

16.6

Tool: tag auditor

In plain words

Checks that every EC2 instance, volume and bucket carries required tags (Owner, Env, CostCenter) with allowed values, and reports the violations per owner or account.

The problem it solves

Without consistent tags, cost cannot be allocated, orphaned resources cannot be traced, and policies cannot target environments.

What it does

  • A policy dictionary lists required keys and, optionally, allowed values or a regex.
  • audit(resources, policy) returns a list of violations, each naming the resource and the problem.
  • The AWS layer can use the Resource Groups Tagging API get_resources (paginated) to see many resource types in one call.
  • Results can feed a report, a chat message, or an auto tagging step.

Core (runs offline)

pythontag_audit.py
from __future__ import annotations

import re

POLICY = {
    "Owner": {"pattern": r"^[a-z0-9._-]+@example\.com$"},
    "Env": {"allowed": {"dev", "staging", "prod"}},
    "CostCenter": {"pattern": r"^\d{4}$"},
}


def audit(resources: list[dict], policy: dict = POLICY) -> list[tuple[str, str]]:
    problems = []
    for r in resources:
        tags = {t["Key"]: t["Value"] for t in r.get("Tags", [])}
        for key, rule in policy.items():
            if key not in tags:
                problems.append((r["ResourceARN"], f"missing {key}"))
                continue
            value = tags[key]
            if "allowed" in rule and value not in rule["allowed"]:
                problems.append((r["ResourceARN"], f"{key}={value!r} not allowed"))
            if "pattern" in rule and not re.match(rule["pattern"], value):
                problems.append((r["ResourceARN"], f"{key}={value!r} bad format"))
    return problems

    {"ResourceARN": "arn:aws:ec2:eu-west-1:1:volume/vol-9",
     "Tags": [{"Key": "Env", "Value": "production"}]},

16.7

Tool: S3 storage reporter

In plain words

Sums object sizes per bucket and prefix, and estimates cost by storage class, so you see where data is and which prefix to put under a lifecycle rule.

The problem it solves

The S3 console cannot group by prefix cheaply, and forgotten log or backup prefixes grow quietly for years.

What it does

  • list_objects_v2 paginated, aggregating Size and StorageClass into a dictionary.
  • Approximate monthly prices per GB by class (Standard, Standard-IA, Glacier Instant and so on); update for your region.
  • For big buckets prefer S3 Storage Lens or S3 Inventory; listing every object costs requests and time.
  • Output sorted by cost with a total.

Core (runs offline)

pythons3_report.py
from __future__ import annotations

from collections import defaultdict

PRICE_GB_MONTH = {"STANDARD": 0.023, "STANDARD_IA": 0.0125, "GLACIER_IR": 0.004, "GLACIER": 0.0036, "DEEP_ARCHIVE": 0.00099}
GIB = 1024**3


def report(objects: list[dict], depth: int = 1) -> list[tuple[str, float, float]]:
    sizes: dict[tuple[str, str], int] = defaultdict(int)
    for o in objects:
        prefix = "/".join(o["Key"].split("/")[:depth]) + "/"
        sizes[(prefix, o.get("StorageClass", "STANDARD"))] += o["Size"]
    by_prefix: dict[str, list[float]] = defaultdict(lambda: [0.0, 0.0])
    for (prefix, cls), size in sizes.items():
        gib = size / GIB
        by_prefix[prefix][0] += gib
        by_prefix[prefix][1] += gib * PRICE_GB_MONTH.get(cls, 0.023)
    return sorted(((p, g, c) for p, (g, c) in by_prefix.items()), key=lambda x: x[2], reverse=True)

    {"Key": "logs/2025/a.gz", "Size": 800 * GIB // 10, "StorageClass": "STANDARD"},
    {"Key": "logs/2026/b.gz", "Size": 300 * GIB // 10, "StorageClass": "STANDARD"},
    {"Key": "backups/db1.dump", "Size": 120 * GIB, "StorageClass": "GLACIER"},
    {"Key": "images/x.png", "Size": 5 * GIB, "StorageClass": "STANDARD_IA"},
]
total = 0.0
for prefix, gib, cost in report(sample):
    total += cost
    print(f"{prefix:12} {gib:8.1f} GiB  ${cost:7.2f}/month")

16.8

Tool: two phase snapshot cleaner

In plain words

Old EBS snapshots cost money. The cleaner works in two phases: first it tags candidates with a deletion date, and only a later run deletes those whose date has passed and that are not in use by an AMI.

The problem it solves

Deleting directly is irreversible. A mistaken filter could remove the only backup.

What it does

  • Phase one tags delete-after=YYYY-MM-DD (7 days ahead) on snapshots older than the retention period; owners have time to object by removing the tag or adding keep=true.
  • Phase two deletes only snapshots whose tag date has passed, using DryRun unless --apply.
  • Skips snapshots used by AMIs (check describe_images(Owners=["self"]) block device mappings).
  • Logs every action with the snapshot id, so there is an audit trail.

Core (runs offline)

pythonsnapshot_clean.py
from __future__ import annotations

from datetime import date, datetime, timedelta, timezone

GRACE_DAYS = 7


def plan(snapshots: list[dict], ami_snapshot_ids: set[str], today: date, retention_days: int = 180):
    to_tag, to_delete = [], []
    for s in snapshots:
        sid = s["SnapshotId"]
        tags = {t["Key"]: t["Value"] for t in s.get("Tags", [])}
        if tags.get("keep", "").lower() == "true" or sid in ami_snapshot_ids:
            continue
        marker = tags.get("delete-after")
        if marker:
            if date.fromisoformat(marker) <= today:
                to_delete.append(sid)
            continue
        age = (today - s["StartTime"].date()).days
        if age > retention_days:
            to_tag.append((sid, (today + timedelta(days=GRACE_DAYS)).isoformat()))
    return to_tag, to_delete

old = datetime(2025, 1, 1, tzinfo=timezone.utc)

    {"SnapshotId": "snap-1", "StartTime": old},
    {"SnapshotId": "snap-2", "StartTime": old, "Tags": [{"Key": "delete-after", "Value": "2026-02-20"}]},
    {"SnapshotId": "snap-3", "StartTime": old, "Tags": [{"Key": "keep", "Value": "true"}]},
    {"SnapshotId": "snap-4", "StartTime": old},
    {"SnapshotId": "snap-5", "StartTime": datetime(2026, 2, 1, tzinfo=timezone.utc)},
]

    for p in ec2.get_paginator("describe_images").paginate(Owners=["self"])
    for img in p["Images"] for bd in img.get("BlockDeviceMappings", []) if "Ebs" in bd and "SnapshotId" in bd["Ebs"]
}

    if apply:
