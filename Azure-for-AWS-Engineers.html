History: Project Red Dog and Windows Azure (2008 to 2010)

  • 2008: At PDC, Microsoft unveiled "Windows Azure". Internally it grew from a project called Red Dog, led by Dave Cutler (the architect of Windows NT), under Ray Ozzie's cloud strategy.
  • February 2010: Windows Azure became generally available.
  • The first offering was platform as a service: Web Roles, Worker Roles, Azure Storage (blobs, tables, queues) and SQL Azure.
Under the hood. AWS began with infrastructure primitives (S3 in March 2006, EC2 in August 2006). Azure began with a managed platform for .NET developers. That difference still shows in Azure's emphasis on App Service, managed identity and tight developer integration.

Global Infrastructure: Regions and Zones

  • A region is a set of datacentres in a latency-defined area (for example West Europe, Central India, East US 2).
  • Microsoft advertises 60 or more regions, a larger count than most competitors (verify the current figure).
  • A geography is a data residency boundary containing one or more regions.
  • Availability zones are physically separate locations within a region, each with independent power, cooling and networking.
  • Not every region has zones, and not every service is zone-redundant. Always check.
az account list-locations --query "[?metadata.regionType=='Physical'].{n:name,geo:metadata.geographyGroup}" -o table
az vm list-skus -l centralindia --zone -o table | head

Region Pairs and Sovereign Clouds

  • Region pairs (for example Central India and South India) get sequential platform updates and prioritised recovery. Newer regions have no pair; they use zones instead.
  • Geo-redundant storage replicates to the paired region.
  • Sovereign clouds: Azure Government (US), Azure operated by 21Vianet (China), and the Microsoft Cloud for Sovereignty and EU Data Boundary options.
  • Compare AWS GovCloud and the AWS China regions.
Expert tip. Design disaster recovery around your own chosen secondary region, not only the platform pair. Confirm that the target region has the SKUs and quota you will need on the day of failover.

Availability Zones: Azure versus AWS

NamingAzure uses logical zone numbers 1, 2 and 3. AWS uses names like ap-south-1a.
MappingLogical numbers map to physical zones per subscription, so "zone 1" in two subscriptions may be different buildings. AWS has the same idea per account.
SubnetsAzure subnets span all zones in a region. AWS subnets live in one AZ.
Zonal versus zone-redundantAzure distinguishes zonal resources (pinned to one zone) from zone-redundant services (spread by the platform).

Azure Resource Manager (ARM)

Every Azure operation, whether from the portal, CLI, Terraform or an SDK, goes through ARM at management.azure.com.

  • RBAC checks and Azure Policy evaluation happen at ARM, before the resource provider does its work.
  • Operations are usually asynchronous: poll the operation URL, or use --no-wait.

Resource Providers, Types and API Versions

  • Resource IDs have a fixed shape, much like an ARN: /subscriptions/{id}/resourceGroups/{rg}/providers/{provider}/{type}/{name}.
  • Each service is a resource provider (Microsoft.Compute, Microsoft.Network, Microsoft.Storage).
  • A provider must be registered in the subscription before you can use it.
  • Every call and template pins an API version, so old templates keep working while new features appear in newer versions.
az provider list --query "[?registrationState=='Registered'].namespace" -o tsv
az provider register --namespace Microsoft.ContainerService
az provider show -n Microsoft.Compute --query "resourceTypes[?resourceType=='virtualMachines'].apiVersions[0]"

Azure RBAC Model

An access decision is built from who (security principal), what (role definition), and where (scope).

Security principal — A user, group, service principal or managed identity.
Role definition — A named set of Actions and DataActions, such as Reader, Contributor, Owner, or a custom role.
Scope — Management group, subscription, resource group or single resource.
Role assignment — The binding of principal, role and scope.
Inheritance — Assignments flow down; permissions are additive (allow), except explicit deny assignments.
  • There is no explicit deny in a role like in an IAM policy. Azure uses deny assignments created by Blueprints or Managed Applications, and Azure Policy for guardrails.

Managed Identities (the Azure IAM Role Equivalent)

A managed identity is an identity Azure creates and rotates for a resource. The app requests a token from a local metadata endpoint. No secret is ever stored.

  • System-assigned: tied to one resource; deleted with it.
  • User-assigned: a standalone resource that many resources can share; best for AKS and repeatable patterns.

Service Principals and App Registrations

  • An app registration defines an application globally in the tenant. A service principal is its local instance that receives role assignments.
  • Automation outside Azure (for example CI) can use a service principal with a secret or certificate.
  • Prefer workload identity federation (OIDC) so GitHub Actions or Azure Pipelines exchange a short-lived token and never hold a secret.
az ad sp create-for-rbac --name sp-ci --role Contributor --scopes /subscriptions/$SUB/resourceGroups/rg-app
az ad app federated-credential create --id <appId> --parameters fic.json
Pitfall. Client secrets expire (commonly 6 to 24 months). An expired secret is one of the most frequent causes of a broken pipeline. Prefer federation, or alert on expiry.

VNet Basics

  • A VNet is regional, with one or more address spaces. Subnets are slices of that space and span all zones of the region.
  • Azure reserves five addresses per subnet (first four and last).
  • All subnets in a VNet can route to each other by default via system routes.
  • There is no internet gateway. Outbound to the internet uses default outbound access (being retired for new VNets), a NAT Gateway, a load balancer, or a public IP.

Networking Gotchas for AWS Users

  • Subnets are not zonal, so you do not create one subnet per AZ; zone choice is per resource.
  • NSG rules have priorities and can deny; order matters. AWS security groups have no order.
  • Peering is non-transitive and needs gateway transit settings for shared VPN or ExpressRoute.
  • Private endpoint success depends on DNS linking. Most failures are DNS.
  • Public IP SKUs must match the load balancer SKU (Standard with Standard).
  • Address ranges cannot overlap between peered VNets or with on premises ranges you route.
  • Changing a subnet with delegation (for example to Microsoft.Web) restricts its use.

IaC Gotchas for AWS Users

  • Resource groups are not stacks; deleting a template resource does not delete it in incremental mode.
  • API versions matter; an old version may lack properties.

Concept: Resource Groups Replace Tags for Grouping

In AWS you search by tag or stack. In Azure you first put a resource in a group, which becomes the natural unit for deletion, access and cost reporting.

  • Typical group patterns: per application and environment (rg-shop-prod), or per layer (rg-network, rg-data).

az resource move --destination-group rg-new --ids $ID
az group export -n rg-app > exported.json

Concept: Control Plane versus Data Plane Everywhere

  • Azure repeats the split: ARM actions manage resources; data actions touch content (blobs, secrets, messages, queries).
  • Roles often come in pairs, such as Contributor versus Storage Blob Data Contributor.
  • For SQL, Cosmos and others, data access can also be separate (database users, Cosmos DB RBAC).
Pitfall. "Owner of the subscription but Forbidden on the blob" is not a bug. Assign the data role.

Q&A: Foundations and History

Q. What was the original name of Azure and when was it released?

Windows Azure, announced in 2008 and generally available in February 2010. It was renamed Microsoft Azure in 2014.

Q. Why did Azure start as PaaS?

It targeted .NET developers with web and worker roles and managed storage, rather than offering raw virtual machines. IaaS VMs arrived in preview in 2012.

Q. What is the relationship between a tenant and subscriptions?

A tenant is the Entra ID directory. Many subscriptions can trust one tenant, and each subscription is a billing and quota boundary.

Q&A: Resource Management

Q. What is ARM?

Azure Resource Manager, the control plane API through which the portal, CLI, SDKs and templates all operate, enforcing RBAC and policy.

Q. What is the difference between a resource group and a stack?

A resource group is a container with lifecycle and access scope. A deployment or deployment stack is the act or managed set of provisioning operations.

Q. Why do I get a "not registered for namespace" error?

The resource provider is not registered in that subscription. Run az provider register -n Microsoft.X.

Q&A: Identity

Q. What replaces IAM roles for workloads?

Managed identities, with RBAC role assignments granting permissions.

Q. What is the difference between Owner and Contributor?

Owner can also assign roles. Contributor can create and manage resources but not grant access.

Q. How does a pipeline authenticate without secrets?

Workload identity federation (OIDC), where GitHub or Azure DevOps issues a token the Entra federated credential trusts.

11. Q&A by Topic · 228

Q&A: Governance

Q. How is Azure Policy different from RBAC?

RBAC controls who can perform actions. Policy controls what resource properties are allowed, audited or auto-remediated.

Q. What is the closest SCP equivalent?

Azure Policy with Deny effect at management group scope, combined with limited RBAC.

Q. How do you implement guardrails for new subscriptions?

Place them under a management group with initiatives assigned, and use subscription vending.

Q&A: Compute

Q. A VM is stopped in the OS but still billed. Why?

It is stopped, not deallocated. Use az vm deallocate to release compute billing.

Q. When choose Container Apps over AKS?

When you want containers, scaling to zero and revisions without managing a cluster or Kubernetes API.

Q. What is the Azure equivalent of Fargate?

Container Apps or Container Instances, depending on whether you need scaled services or single containers.

11. Q&A by Topic · 230

Q&A: Networking

Q. Why can't my VMs in peered spokes talk to each other?

Peering is non-transitive. Route through a hub firewall or NVA with UDRs, or peer the spokes directly.

Q. What is the difference between a service endpoint and a private endpoint?

A service endpoint keeps public IP addressing but restricts to your subnet over the backbone. A private endpoint gives the service a private IP in your VNet.

Q. Why does name resolution fail after creating a private endpoint?

The Private DNS zone is missing, not linked to the VNet, or custom DNS does not forward to Azure DNS.

Q&A: Storage and Data

Q. What is the difference between LRS, ZRS and GRS?

LRS keeps three copies in a datacentre, ZRS spreads across zones, GRS adds an asynchronous copy in the paired region.

Q. Why is Cosmos DB expensive when I query?

Cross-partition queries and scans consume many Request Units. Choose a partition key matching your queries and use point reads.

Q. How do I give temporary blob access?

A SAS token, preferably a user delegation SAS signed with Entra credentials and short expiry.

Boards, Repos, Pipelines, Test Plans and Artifacts.

Add checks to an environment; a deployment job targeting that environment waits for the checks.

A secured definition of how a pipeline authenticates to an external system such as Azure or a registry. Prefer workload identity federation.

A pipeline has stages, a stage has jobs that run on agents, and jobs have steps (tasks or scripts).

No free parallel job or no agent meeting demands. Check parallelism limits and the agent pool.

Extends templates with required steps and environment checks that require the template.

Bicep for Azure-only teams wanting day-one resource support and no state. Terraform when multi-cloud or existing skills matter.

It previews the changes a deployment would make without applying them.

Soft delete reserves the name. Purge the vault or use a different name.

import azure.functions as func
app = func.FunctionApp()

@app.route(route="hello", auth_level=func.AuthLevel.FUNCTION)
@app.queue_output(arg_name="msg", queue_name="out", connection="AzureWebJobsStorage")
def hello(req: func.HttpRequest, msg: func.Out[str]) -> func.HttpResponse:
    msg.set("processed")
    return func.HttpResponse("hello")
