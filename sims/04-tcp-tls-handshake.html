Notes

  • 0-RTT replay: early data in TLS 1.3 (RFC 8446 §2.3, §8) is not replay-safe. A network attacker can duplicate it, so servers should only accept idempotent requests in 0-RTT.
  • TLS 1.3 resumption still takes one round trip; 0-RTT removes the wait only for the first client flight.

Simplifications

  • Packets are shown as one message per arrow; real stacks batch, retransmit and split packets, and TCP/TLS records can be coalesced.
  • TLS 1.2 is shown with an ECDHE suite and no session tickets; extensions, HelloRetryRequest, client certificates and TLS record sizes are omitted.
  • Time is modelled as half an RTT per one-way trip; no bandwidth, loss, congestion window, certificate size or handshake CPU time. Server think time is a single example number.
  • The first HTTP request is assumed to fit in one flight; DNS lookup time is excluded; QUIC is shown only at the level of its handshake (no packet numbers, address validation or Retry).
  • 0-RTT is shown as accepted by the server; servers may reject it, and early data is replayable (RFC 8446 §8).

All numbers on this page are examples chosen for teaching, not measurements.
