Simplifications

  • Pods are created and removed instantly (no scheduling, image pull or termination grace period). Readiness is a fixed delay; minReadySeconds is 0, so Available equals Ready.
  • The controller loop follows the documented rules (scale up the new ReplicaSet to at most replicas + maxSurge, then scale down old pods while keeping at least replicas - maxUnavailable available, unhealthy old pods first) but one sync is shown per simulated second.
  • Progress deadline: the clock restarts whenever the new ReplicaSet is scaled up or one of its pods becomes Ready; the simulator shows the ProgressDeadlineExceeded condition and stops. The real Deployment controller does not roll back by itself.
  • If percentages resolve to maxSurge 0 and maxUnavailable 0, the controller uses maxUnavailable 1 (both cannot be 0). Rollback is modelled as kubectl rollout undo returning to the previous template; any pods of that earlier ReplicaSet still running count as already updated.
  • Replica counts, seconds and percentages are example values.

All numbers shown are examples, not measurements. Keys: Space play/pause, Left back, Right step, R reset.
