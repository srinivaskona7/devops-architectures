1. Linux Fundamentals · 3

What the Kernel Does

The kernel is the resource manager and referee.

  • Process management: scheduling CPU time, creating and destroying processes.
  • Memory management: virtual memory, paging, page cache, OOM killer.
  • Filesystems: the VFS layer unifies ext4, XFS, NFS, tmpfs and others.
  • Device drivers: block, character and network devices.
  • Networking: TCP/IP stack, netfilter firewall, routing.
  • Security: permissions, capabilities, SELinux/AppArmor, namespaces.
1. Linux Fundamentals · 4

Monolithic Kernel with Modules

Linux is a monolithic kernel: drivers run in kernel space for speed. Loadable modules add features at runtime without a reboot.

lsmod                 # list loaded modules
modinfo xfs           # describe a module
modprobe br_netfilter # load with dependencies
modprobe -r br_netfilter  # unload
uname -r              # running kernel version

lsmod reads /proc/modules. modprobe resolves dependencies from modules.dep and calls the finit_module system call.

1. Linux Fundamentals · 5

System Calls

Expert tip. Every failed syscall sets errno. strace -f -tt -e trace=file,network -p PID shows exactly which call failed and why (ENOENT, EACCES, ECONNREFUSED).

A system call is the controlled doorway into the kernel. read, write, open, fork, execve, mmap and socket are examples.

Program calls open()→libc wrapper→CPU trap instruction→Kernel handler→Result returned
strace -c ls /etc      # count syscalls
strace -e openat cat /etc/hostname

strace uses the ptrace system call to intercept every syscall of a target. It is the best first tool when a program fails mysteriously.

Boot Process

Firmware — UEFI initialises hardware, reads the EFI System Partition and loads the bootloader.
GRUB2 — Reads grub.cfg, shows the menu, loads the kernel and initramfs into memory.
Kernel — Decompresses, sets up memory, CPUs and drivers, mounts the initramfs.
initramfs — Loads storage drivers, unlocks LUKS, assembles LVM and RAID, mounts the real root.
systemd (PID 1) — Starts units in parallel by dependency until default.target is reached.
Login — getty, sshd or a display manager accepts users.
Firmware UEFI/BIOS→Bootloader GRUB2→Kernel + initramfs→systemd PID 1→Targets and services→Login
  • The initramfs is a temporary root filesystem with the drivers needed to mount the real root.
  • The kernel starts /sbin/init, which is systemd on nearly all modern distributions.
  • Inspect timing with systemd-analyze blame.

1. Linux Fundamentals · 8

What Is a Process

A process is a running program: an address space, open files, credentials, and one or more threads.

  • PID: unique id. PPID: parent id. UID/GID: owner.
  • Created with fork() (clone the caller) then execve() (load a new program).
  • Kernel stores each one in a task_struct.

mv and rm

mv -n a b             # never overwrite
rm file
rm -rf dir            # DANGEROUS

Redirection and Pipes

Shell parses — Splits the line at pipes and finds redirections.
pipe() — The kernel creates a buffer (64 KiB by default) with a read end and a write end.
fork() twice — One child for each command in the pipeline.
dup2() — Each child's stdout or stdin is wired to the pipe end; redirections open files onto fds 0, 1, 2.
execve() — Each child runs its program. A full pipe blocks the writer, an empty pipe blocks the reader.
wait — The shell waits and reports the exit status of the last command (or any with pipefail).

Each process has three standard streams: 0 stdin, 1 stdout, 2 stderr.

cmd > out.txt          # overwrite
cmd >> out.txt         # append
cmd 2> err.txt
cmd > all.txt 2>&1     # both
cmd1 | cmd2            # pipe
cmd | tee file         # split to file and screen

A pipe is a kernel buffer between two processes created by pipe(); the producer blocks when it is full.

Inventory — Know every host, OS version, owner and criticality.
Triage advisories — Read CVE severity and whether the vulnerable code is actually used.

PAM and Password Policy

Application — sshd calls pam_authenticate().
Stack lookup — PAM reads /etc/pam.d/sshd which includes system-auth.
auth modules — pam_faillock, pam_unix, pam_sss are tried in order.
account modules — Checks expiry, lock state and access rules.
password modules — pam_pwquality enforces complexity on change.
session modules — pam_limits applies ulimits, pam_systemd registers the session.

PAM (Pluggable Authentication Modules) is a stack of checks in /etc/pam.d/ that apps like sshd and login call.

  • pam_pwquality: complexity (minlen, minclass).
  • pam_faillock: lock after repeated failures.
  • pam_limits: resource caps from /etc/security/limits.conf.

Order matters: control flags required, requisite, sufficient, optional.

Deep Dive: Virtual Memory

Every process sees a private, contiguous address space. The MMU translates virtual pages to physical frames using page tables the kernel maintains.

  • Minor fault: page is in RAM but not yet mapped (cheap).
  • Major fault: page must be read from disk (expensive); watch sar -B and pidstat -r.
  • Copy-on-write makes fork() cheap: parent and child share pages until one writes.
Under the hood. The page cache uses almost all free RAM on purpose. "Free" memory is wasted memory; the metric that matters is available in free -h and swap-in activity (vmstat columns si/so).

Deep Dive: The CPU Scheduler (CFS and EEVDF)

The scheduler decides which runnable task gets each CPU and for how long. Recent kernels use EEVDF, earlier ones the Completely Fair Scheduler, both based on fair virtual runtime.

  • Each CPU has a run queue; the load balancer migrates tasks between CPUs.
  • Real-time policies (SCHED_FIFO, SCHED_RR) always preempt normal tasks.
  • cgroup cpu.weight and cpu.max divide CPU between groups.
chrt -p PID                # show policy
taskset -cp 0-3 PID        # pin to CPUs
mpstat -P ALL 1            # per-CPU utilisation
pidstat -w 1               # context switches
Pitfall. High involuntary context switches mean tasks are being preempted because CPUs are oversubscribed. High voluntary switches mean tasks block often, usually on I/O or locks.

tcpdump: Concept

Packet arrives — The NIC DMAs it into a ring buffer and raises an interrupt.
Kernel stack — Normal protocol processing continues unaffected.
AF_PACKET tap — A copy goes to every packet socket whose BPF filter matches.
BPF filter — Your expression, such as port 53, was compiled to bytecode and runs in the kernel.
libpcap — Delivers matching packets to the tcpdump process through a ring buffer.
Decode — tcpdump prints headers or writes a pcap file.
Pitfall. A busy interface can outrun tcpdump and show "packets dropped by kernel". Add a tight filter, use -s 96 for headers only, or write to a file with -w.

tcpdump uses libpcap to open an AF_PACKET socket and a BPF filter compiled into the kernel, so only matching packets are copied to user space.

NIC→Kernel BPF filter→libpcap→tcpdump→Screen or .pcap

Needs root or CAP_NET_RAW.

Deep Dive: How bash Expands a Command Line

1 Brace expansion — {a,b}.txt becomes a.txt b.txt.
2 Tilde expansion — ~ becomes the home directory.
3 Parameter, arithmetic, command substitution — $var, $((1+2)), $(cmd).
4 Word splitting — Unquoted results split on IFS (space, tab, newline).
5 Pathname expansion — Wildcards such as * are matched against files.
6 Quote removal — Remaining quotes are stripped, then the command runs.
Pitfall. Word splitting and globbing happen after variable expansion, which is why an unquoted $file with spaces becomes several arguments.

Q&A 1.1 Fundamentals: Kernel and Processes

Q. What is the difference between user space and kernel space?

Kernel space runs privileged code with direct hardware access. User space runs applications with restricted rights and must request services through system calls.

Q. How does a new process get created?

The parent calls fork(), which clones its process, then the child calls execve() to replace its memory image with a new program.

7. Q&A by Topic · 259

Q&A 1.2 Fundamentals: Process States

Q. A process is in D state and cannot be killed. Why?

It is in uninterruptible sleep, usually waiting on storage or NFS I/O inside the kernel. Fix the underlying I/O problem; signals are delivered only after the call returns.

Q. Does killing a zombie free it?

No. A zombie is already dead; it only holds a process-table entry until its parent calls wait(). Restart or fix the parent, or let init adopt it.

7. Q&A by Topic · 260

Q&A 1.3 Fundamentals: Signals and Priority

Q. Why prefer SIGTERM over SIGKILL?

SIGTERM lets the process flush buffers and release locks. SIGKILL cannot be caught and can leave corrupt state.

Q. What does a nice value of 19 mean?

The lowest scheduling priority. The task receives CPU only when higher priority tasks leave capacity.

Q&A 1.4 Fundamentals: Filesystem

Q. Why can df show free space while writes fail?

Inodes are exhausted. Check df -i. Another cause is a quota or reserved blocks.

Q. How is a hard link different from a symlink?

A hard link is another directory entry for the same inode and works only inside one filesystem. A symlink is a separate file containing a path and can dangle.

New files get 640 and new directories 750, meaning others get no access.

Scenario Method: How an Expert Works an Incident

Stabilise — Stop the bleeding: fail over, shed load, or disable the faulty change.
Scope — What is affected, since when, how many users, what changed.
Observe — Collect metrics and logs before touching anything.
Hypothesise — Rank causes by likelihood and cost to test.
Test — Change one thing, measure, and keep notes.
Fix and verify — Apply the fix, confirm with the user-facing symptom.
Review — Blameless post-mortem, add monitoring and automation.
